# skillbase 운영 가이드

## 검증 운영

- `정적 검사`: 원격 `SKILL.md`를 실행하지 않고 frontmatter, 위험 명령, 비밀값 접근 패턴을 점검합니다.
- `공식 격리 검증`: Cloudflare Sandbox에서 사전 설치된 `skills` CLI를 실행합니다.
- `무결성 fallback`: 공식 CLI가 제한 시간 안에 끝나지 않으면 원본 해시를 재확인하고 `SKILL.md`만 격리 경로에 기록합니다. 이 결과는 공식 CLI 성공과 구분해 표시합니다.
- Sandbox Queue가 30분 안에 완료되지 않으면 stale 작업으로 만료 처리되며, 운영자 큐에서 다시 요청할 수 있습니다.

운영자 화면의 최근 30일 지표에서 공식 CLI 성공, fallback, 실패·대기 건수와 평균 소요 시간을 확인합니다. fallback 비율이 높으면 먼저 CLI 실행 로그와 허용 호스트를 점검한 뒤 timeout을 조정합니다.

AI 한국어 요약은 `생성 → 운영자 검토 → 승인` 상태로 관리합니다. 실패한 요약은 운영자 화면에서 개별 또는 일괄 재시도할 수 있고, 내용이 부정확하면 `재생성 요청`으로 다시 대기열에 넣습니다. 모델·바인딩 장애는 운영 알림으로 기록하며, 요약이 아직 없는 동안에는 기존 설명 기반 임시 요약을 표시합니다.

수집·검증 실패는 `ops_alerts`에 자동 기록됩니다. 운영자 화면에서 미해결 알림을 확인 처리할 수 있고, `SKILLBASE_ALERT_WEBHOOK_URL`을 Sites secret으로 설정하면 같은 알림을 외부 Webhook에도 전송합니다. 동일 원인의 알림은 6시간 동안 묶어 중복 전송을 막습니다.

## 공개 기준

1. 원본 URL과 `SKILL.md`의 이름·디렉터리가 일치하는지 확인합니다.
2. 정적 차단 신호가 없어야 합니다.
3. 승인 후 공개 전 검증 상태가 `legacy`, `static_passed`, `sandbox_passed`, `sandbox_fallback_passed` 중 하나여야 합니다.
4. fallback 통과는 운영자 확인이 필요한 상태로 취급합니다.

## 데이터 백업

운영자 큐 상단의 `데이터 백업`을 누르면 Skill, 승인 이력, 검증 이력, 피드백, 운영 알림, 품질 이슈, 사용량, 즐겨찾기, 사용자 제출, 수집 상태가 JSON으로 다운로드됩니다. `복구 테스트`는 현재 백업을 운영 DB에 쓰지 않고, 격리된 staging D1에서 실행할 순서·대상 테이블·행 수·필수 필드·중복 ID·참조 무결성·JSON 해시를 계산하는 dry-run 복구 리허설입니다. 실제 staging D1에 쓰는 리허설은 별도 복구용 D1을 연결한 뒤 수행해야 합니다. 최소 주 1회와 대규모 수집 직후 백업을 보관하고, 복구 테스트가 실패하면 공개 배포를 중지합니다.

## 품질 점검

- 자동 수집 뒤 동일 이름·해시의 중복 Skill을 찾고 대표 원본을 표시합니다.
- 원본 링크는 최초 수집 후 7일마다 재확인하며, 깨진 링크는 공개 차단 이슈로 기록합니다.
- 라이선스가 바뀌면 이전 값과 새 값을 보존하고 운영자 검토 알림을 만듭니다.
- 공개 전에 열린 품질 차단 이슈가 없어야 합니다.

## 신고·사용량

- 사용자 신고는 익명 식별자를 원문 IP 대신 해시로 저장하고, 식별자당 시간당 5건으로 제한합니다. 동일 신고의 반복 제출도 차단합니다.
- 조회·복사·앱 열기·설치 확인 이벤트는 최근 30일 추천 점수와 운영 통계에 사용됩니다.
- 즐겨찾기는 로그인한 사용자별로 저장되며, 추천순은 즐겨찾기 3배와 사용량을 검증 상태와 함께 반영합니다.
- 신고 API는 JSON 요청·길이·honeypot·중복·시간당 횟수를 함께 검사하고, 신고가 접수되면 운영 알림을 생성합니다.

## 사용자 제출·공개 API

- 사용자는 HTTPS 원본 URL과 설치·프롬프트 정보를 제출할 수 있습니다. 제출은 하루 3건으로 제한되고, 운영자가 승인해도 즉시 공개되지 않고 검증 큐로 이동합니다.
- 외부 서비스는 `/api/v1/skills`에서 공개 승인된 Skill을 검색할 수 있습니다. `q`, `category`, `region`, `platform`, `verification`, `sort`, `limit` 필터를 지원하며 60초 캐시를 사용합니다. 호출자는 해시된 네트워크 식별자 기준 한 시간 120회로 제한되며 `X-RateLimit-*` 헤더를 확인합니다. 제출·피드백도 D1 영속 제한기를 사용합니다.

## 정기 유지보수

- Dependabot이 루트, Sandbox adapter, GitHub Actions 의존성 업데이트 PR을 매주 생성합니다.
- 매주 예약된 GitHub Actions가 `npm audit`를 실행하고, 공개 `skills` CLI 버전과 Docker에 고정한 버전이 다르면 Issue를 만듭니다.
- 같은 작업에서 사이트 빌드·린트·회귀 테스트와 Sandbox adapter 테스트도 실행합니다.
- CLI 버전을 올릴 때는 Adapter 테스트와 공식 CLI/fallback 지표를 확인한 뒤 Worker를 배포합니다.

## 배포와 소스

- GitHub `main`은 공개 코드·CI 기준 저장소입니다.
- Sites 원격 저장소는 운영 배포 소스입니다.
- 변경 후 CI가 성공했는지 확인하고, Sites에도 같은 커밋을 반영합니다.
- 운영 runtime secret은 소스에 저장하지 않습니다.

## 관리자 보안 경계

- 관리자 API는 플랫폼이 전달하는 인증 사용자 ID를 기본 식별자로 사용하고, 명시적으로 허용한 경우에만 이메일을 보조 식별자로 사용합니다.
- 관리자 API는 cross-site 요청을 거부하고, 응답을 캐시하지 않습니다. 운영자 식별자·Webhook·Sandbox 토큰은 Sites secret으로만 관리합니다.
- 현재 Site 접근 정책은 소유자 1명 전용입니다. MFA는 애플리케이션이 우회할 수 없는 ChatGPT/Cloudflare 계정 보안 설정이므로 해당 계정에서 활성화해야 합니다.
- 팀별 비공개 공간은 현재 멤버십·역할·초대 및 팀 공유를 제공하는 인증 경계가 없어 활성화하지 않았습니다. 이 기능은 Site 접근을 팀 단위로 바꾸고 멤버십 모델을 확정한 뒤 별도 구현해야 합니다.
