# 1인 운영 런북

이 서비스는 운영자 1명이 관리하는 것을 전제로 합니다. 자동화가 실패해도 공개 데이터가 오염되지 않도록, 기능 추가보다 아래의 중단 기준을 우선합니다.

## 출시 전 1회

1. Sites runtime secret에 수집·검증 토큰과 AI 요약 provider를 설정합니다. API 키는 소스와 채팅에 저장하지 않습니다.
2. `/admin`에서 최근 수집 결과, 검토 큐, 품질 차단 이슈, AI provider 상태를 확인합니다.
3. 백업을 내려받고 복구 테스트를 통과시킵니다.
4. `npm run health:release`가 통과한 뒤에만 배포합니다.
5. 배포 후 `/api/health`, `/api/v1/manifest`, 공개 Skill 상세 1건을 확인합니다.

## 매주 15분

- `/admin`에서 미해결 알림, 검토 필요 Skill, 검증 fallback 비율을 확인합니다.
- 백업 1개를 보관하고 복구 테스트 결과를 기록합니다.
- GitHub Actions 유지보수 결과와 의존성·Skills CLI 업데이트 Issue를 확인합니다.
- 최근 Worker 오류 로그가 있으면 공개를 멈추고 직전 배포 버전으로 되돌립니다.

## 매월 30분

- 실제 원본 10건의 설치 명령, 라이선스, 원본 링크를 대조합니다.
- 중복·깨진 링크·라이선스 변경 이력을 점검합니다.
- 최근 30일 사용량을 보고 검색 정렬과 추천 규칙을 조정합니다.
- 개인정보 보관 기간과 운영자 접근 권한을 확인합니다.

## 즉시 중단 기준

- 출시 점검에서 AI provider가 `missing`입니다.
- 최근 수집이 `failed` 또는 `completed_with_errors`입니다.
- 공개 대상에 품질 `blocker` 또는 깨진 원본 링크가 있습니다.
- 백업 복구 테스트가 실패했습니다.
- 배포 후 Worker 오류가 반복되거나 API 계약이 깨졌습니다.

## 1인 개발 원칙

- 새 기능은 실제 사용량이나 운영 문제에서 근거가 생긴 뒤 추가합니다.
- 베타는 초대형으로 시작하고, 공개 전환은 운영 지표와 복구 절차가 확인된 뒤 결정합니다.
- 자동 생성 콘텐츠는 항상 `생성 → 운영자 검토 → 공개` 단계를 거칩니다.
- 결제·팀 협업·다국어·대규모 API는 핵심 카탈로그의 안정성이 확인된 뒤로 미룹니다.
